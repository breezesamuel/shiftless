# 检索问题模板（阶段 5）

检索质量决定生成质量。不要把大问题整个塞给 retrieve.py，拆成 3-8 个聚焦的 query。每个 query 的 top-3 片段够写一个论点。

## 竞品类

- `<竞品名>` 是什么 / 主打什么
- `<竞品名>` 定价 价格 方案
- `<竞品名>` 免费 试用 收费
- `<竞品名>` 目标用户 客户 面向谁
- `<竞品名>` 功能 特色 亮点
- `<竞品名>` 更新 新功能 最近
- `<竞品名>` 融资 团队 规模

## 用户/评论类

- `用户 抱怨 差评 问题 缺点`（每个竞品跑一遍）
- `用户 好评 推荐 为什么选择`
- `用户 需要 想要 需求 求推荐`
- `对比 比较 哪个好 区别`
- `迁移 从……换到…… 替代`

## 渠道类

- `流量 规则 算法 扶持`
- `涨粉 变现 收入 收益`
- `新人 入门 冷启动 账号`
- `更新频率 最佳发布时间`

## 定位/机会类

- `不足 缺 空白 没人做`
- `痛点 麻烦 费时 成本高`
- `一站式 简单 自动化 更快`

## 技巧

1. **先宽后窄**：先跑 1 个宽 query 探测语料覆盖，再拆细。
2. **c 名称精确匹配**：中文分词是单字粒度的，`openai` 这种英文串是完整 token，效果最好；中文长词拆成单字也能命中但噪音大，靠 top-5 过滤。
3. 每个竞品至少跑一遍"主打 / 定价 / 用户评价"，机会类问题最后跑。
4. retrieve 输出带 `source=文件名:块号`，生成时把这些块读全再写对应段落。
5. 如果某个 query 零命中，先确认是不是没抓到对应页面，回阶段 2 补抓，而不是降低要求猜。
